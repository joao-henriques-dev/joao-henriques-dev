**Period:** Aug 2025 - Oct 2025, Jun 2026 - Present
**Links:** [Website](https://fantasypremierpicks.vercel.app/)

**Tech Stack:**

![Recharts](https://img.shields.io/badge/Recharts-22B5BF?style=for-the-badge)
![PostgreSQL](https://img.shields.io/badge/PostgreSQL-4169E1?style=for-the-badge&logo=postgresql&logoColor=white)
![Supabase](https://img.shields.io/badge/Supabase-3ECF8E?style=for-the-badge&logo=supabase&logoColor=white)
![Upstash Redis](https://img.shields.io/badge/Upstash%20Redis-00E9A3?style=for-the-badge&logo=upstash&logoColor=black)
![Render](https://img.shields.io/badge/Render-46E3B7?style=for-the-badge&logo=render&logoColor=black)
![Vercel](https://img.shields.io/badge/Vercel-000000?style=for-the-badge&logo=vercel&logoColor=white)

**What it does:**  
A free web app that scores every Fantasy Premier League player from 1 to 100 and ranks upcoming fixtures by difficulty.

**How it works:**
- **Data:** makes GET requests to the official FPL API and stores the results in a relational database whose structure I designed, to have comprehensive FPL data.
- **Model:** built in Python with NumPy and Scikit-Learn for efficient data processing, using a Linear Regression ML model.
- **Backend:** a REST API designed with Flask, using SQLAlchemy as the ORM.
- **Database and rate limiting:** PostgreSQL hosted on Supabase, plus Upstash Redis to store user IP addresses for rate limiting, preventing exploitation of the API endpoints.
- **Deployment:** backend on Render, frontend on Vercel.

**Why I built it:**  
So you don't have to eyeball spreadsheets to know if a transfer is actually worth it for your FPL team, saving time and making better, data-driven decisions.

### JunctionX Lisbon 2026 Hackathon - The *-Files (NOS Challenge)
**Period:** Oct 2026 (24-hour hackathon at Instituto Superior Técnico - Taguspark)
**Team:** [João Henriques](https://www.linkedin.com/in/jmhenriques/), [Rogério Soares](https://www.linkedin.com/in/rogerio-barros-soares/), [Salvador Antunes](https://www.linkedin.com/in/salvadornlantunes/)
**Links:** [Website](https://nfcjunction.lovable.app/)

**Tech Stack:**  
![Python](https://img.shields.io/badge/Python-3776AB?style=for-the-badge&logo=python&logoColor=white)
![Google Gemini API](https://img.shields.io/badge/Google%20Gemini%20API-8E75B2?style=for-the-badge&logo=googlegemini&logoColor=white)
![Lovable](https://img.shields.io/badge/Lovable-FF4D8D?style=for-the-badge&logo=lovable&logoColor=white)

**What it does:**  
Anonymises Portuguese documents, such as medical reports, while preserving their original structure and meaning. It combines AI-powered detection with deterministic text masking, so the LLMs decide *what* is sensitive and Python handles the actual replacements.

**How it works:**
1. **Flagging (LLM call 1):** Gemini identifies sensitive information in the report.
2. **Context checking (LLM call 2):** Gemini verifies each flag in context and corrects some of the previous flags, so the document stays anonymous and readable at the same time.
3. **Deterministic masking (Python):** scripts replace the confirmed sensitive data.
4. **Review (LLM call 3):** a final Gemini reviewer checks the results.

**Also built:**
- A synthetic data generator to evaluate the solution.
- A web demo showcasing the end-to-end process.

**Why we built it:**  
Built with my teammates for the NOS challenge at JunctionX Lisbon 2026, among more than 10 teams that participated in this specific contest, driven by the goal to help build privacy-first tools (even though we used a Google product, I know). At the end, we came very close to a top 3 finish, having received wide praise for our solution.
